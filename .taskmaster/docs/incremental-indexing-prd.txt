# Product Requirements Document: Incremental Indexing with File Change Detection

## Overview

Extend qdrant_indexer to properly support incremental indexing - detecting changed, added, and deleted files to update the Qdrant database accordingly. Currently, re-indexing a file that changed its chunk count leaves orphan entries, and deleted files remain in the database.

## Problem Statement

The current indexer has these limitations:

1. **Orphan chunks**: When a file shrinks (fewer chunks), old chunks with higher indices remain in the database
2. **No deletion support**: Deleted files leave their chunks permanently in the database
3. **No change detection**: All files are re-processed on every index run, even if unchanged
4. **No file tracking**: No persistent record of what has been indexed and when

## Goals

1. Detect file changes using content hashing (not just modification time)
2. Properly update the database when files change (remove old chunks, add new ones)
3. Remove database entries when source files are deleted
4. Skip unchanged files to improve re-indexing performance
5. Provide CLI options to control update behavior (full re-index vs incremental)

## Non-Goals

- Real-time file watching / live updates
- Distributed/concurrent indexing
- Partial file updates (always re-index entire file)
- Version history of indexed content

## Technical Approach

### File State Tracking

Maintain a manifest file (JSON) tracking indexed files:

```python
@dataclass
class IndexedFileState:
    path: str                    # Absolute path to file
    content_hash: str            # SHA-256 of file content
    indexed_at: str              # ISO timestamp
    chunk_count: int             # Number of chunks created
    chunk_ids: list[int]         # Point IDs in Qdrant

# Stored in .qdrant-index-state.json or similar
```

### Change Detection Strategy

For each file in the target directory:

1. Compute content hash (SHA-256)
2. Compare against stored state:
   - **Not in state**: New file - index it
   - **Hash matches**: Unchanged - skip it
   - **Hash differs**: Modified - delete old chunks, re-index
3. For files in state but not on disk:
   - **Deleted file**: Remove chunks from database

### Database Update Operations

New methods on `QdrantIndexer`:

```python
def delete_file_chunks(self, file_path: Path) -> int:
    """Delete all chunks for a file from the database.

    Uses filter query on source field to find and delete points.
    Returns number of points deleted.
    """

def get_file_chunk_ids(self, file_path: Path) -> list[int]:
    """Get all point IDs for a file's chunks."""

def sync_directory(
    self,
    path: Path,
    state_file: Path | None = None,
    force: bool = False,
    on_progress: ProgressCallback | None = None,
) -> SyncResult:
    """Synchronize a directory with the database.

    Args:
        path: Directory to sync
        state_file: Path to state file (default: path/.qdrant-index-state.json)
        force: If True, re-index all files regardless of state
        on_progress: Progress callback

    Returns:
        SyncResult with added/updated/deleted/unchanged counts
    """
```

### State File Management

```python
class IndexState:
    """Manages the persistent index state."""

    def __init__(self, state_file: Path):
        self.state_file = state_file
        self.files: dict[str, IndexedFileState] = {}

    def load(self) -> None:
        """Load state from file."""

    def save(self) -> None:
        """Persist state to file."""

    def get_file_state(self, path: Path) -> IndexedFileState | None:
        """Get state for a file."""

    def set_file_state(self, path: Path, state: IndexedFileState) -> None:
        """Update state for a file."""

    def remove_file(self, path: Path) -> None:
        """Remove a file from state."""

    def get_all_paths(self) -> set[str]:
        """Get all tracked file paths."""
```

### CLI Updates

Update the `index` command:

```
qdrant-indexer index PATH [OPTIONS]

Options:
  --incremental / --full    Incremental update vs full re-index (default: incremental)
  --state-file PATH         Custom state file location
  --clean                   Remove entries for deleted files
  --dry-run                 Show what would be done without making changes
```

New `status` command:

```
qdrant-indexer status PATH [OPTIONS]

Shows:
  - Total indexed files
  - Files pending update (modified)
  - Files pending addition (new)
  - Files pending deletion (removed from disk)
  - Last index timestamp
```

New `clean` command:

```
qdrant-indexer clean PATH [OPTIONS]

Options:
  --deleted-only    Only remove entries for deleted files
  --all             Remove all entries for this path (reset)
```

## Testing Requirements

### Unit Tests

1. **State manager tests**:
   - Load/save state file
   - File hash computation
   - State comparison (new/modified/deleted detection)

2. **Indexer deletion tests**:
   - Delete chunks by file path
   - Delete chunks by point IDs
   - Handle non-existent files gracefully

3. **Sync logic tests**:
   - New file detection
   - Modified file detection
   - Deleted file detection
   - Force re-index behavior

### Integration Tests

1. Index directory, modify a file, re-sync - verify old chunks removed
2. Index directory, delete a file, re-sync - verify chunks removed
3. Index directory, add a file, re-sync - verify only new file processed
4. Force re-index - verify all files processed
5. Dry-run mode - verify no changes made

## Success Criteria

1. Modified files: Old chunks removed, new chunks added
2. Deleted files: All chunks removed from database
3. Unchanged files: Skipped during incremental sync
4. State file: Accurately tracks all indexed files
5. Performance: Skip unchanged files in under 100ms per 1000 files
6. No data loss: Never delete chunks without user intent

## Edge Cases

1. **State file missing**: Treat as full re-index, create new state
2. **State file corrupted**: Warn user, offer to reset
3. **File moved**: Detected as delete + add (no move tracking)
4. **File renamed**: Same as move - delete old, add new
5. **Permission errors**: Log and skip, don't fail entire sync
6. **Qdrant connection lost**: Save partial state, allow resume

## Migration Path

For existing users:

1. First run with `--incremental` creates state file
2. Existing data remains (no chunks deleted)
3. Subsequent runs use incremental behavior
4. Use `--full` to force complete re-index if needed

## Dependencies

No new dependencies required. Uses:
- `hashlib` (stdlib) for SHA-256
- `json` (stdlib) for state file
- Existing `qdrant-client` for delete operations
